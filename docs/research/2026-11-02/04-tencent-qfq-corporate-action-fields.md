## 事实、发布方陈述与本项目推断

### 来源支持的事实

1. 腾讯接口在单次短间隔对照中返回了相同的历史 qfq 价格行；原始 JSON 字节哈希可因响应包装变化而不同。
2. 腾讯响应在除息日附近包含公司行动附属对象，且 qfq/bfq 对同一日期呈现不同价格序列和复权比台阶。
3. 巨潮首页自述其为中国证监会指定的上市公司信息披露网站；公告查询接口可返回公告 ID、标题、日期和原件路径。
4. 贵州茅台公告明确区分股东大会日期、股权登记日、除息日和发放日。
5. 园城黄金公告明确区分终止上市决定日、退市整理期开始日、预计最后交易日、停牌日和摘牌日。
6. 盘中临停公告给出 13:00 开始、13:10 恢复的精确时间。

### 发布方/供应方陈述

- 巨潮首页的“中国证监会指定”是网站自述，本轮未从证监会官网独立复核该表述。
- 腾讯响应中的公司行动对象是供应方返回内容；未找到公开字段规范，不能把它当作交易所正式定义。

### 本项目推断（尚未代码验证）

1. 价格快照与公司行动事件账本必须分开建模；公司行动日期不能从 qfq 价格反推，也不能用单一 `adj_close` 代替事件表。
2. 事件账本至少需要：稳定公告主键、原文 URL、事件类型、公告日、登记日、生效日、支付日、开始/恢复时间（停牌）、决定日、整理期起止、最后交易日和摘牌日（退市）。
3. 原始响应哈希与规范化价格行哈希都要保存；仅保存 JSON SHA 会把响应包装变化误判为价格变化，仅保存行哈希又会丢失原件审计能力。
4. 对公告查询结果需清洗 HTML 标签；证券字段缺失时要保留“结构化字段缺失”状态，并从标题/正文解析后标注来源与置信度。
5. 预计日期和事后确认日期应区分；退市整理期“预计最后交易日”不能直接覆盖为实际日期。
6. 对腾讯历史回写问题，下一轮应比较两个真实权益分派事件的“公告日 → 登记日 → 除息日”与 qfq/bfq 比值台阶，而不是从短间隔重复下载直接下结论。

## 可复用结论

- 短期重下载只能提供“本样本本窗口未观察到变化”的证据，不能完成 PIT 认证。
- 腾讯 qfq/bfq 对照可以定位除息日边界上的复权比台阶，但公式和回写政策仍未验证。
- 巨潮可作为公告发现和原文证据入口，但接口契约、许可、全量性和延迟均待核验。
- 公司行动账本不能只存一个日期字段；公告日、登记日、除息日、支付日、停牌起止和退市各阶段必须分开。
- 退市事件至少建模：终止决定日、整理期开始日、预计/实际最后交易日、停牌日、摘牌日。
- 停牌需要精确开始/恢复时间；日频缺失值或 `is_trading=false` 不足。
- 监管公告流可能缺少 `secCode/secName`，标题含 HTML 高亮；应按公告 ID 主键、清洗标题并保留原文 URL。
- 原始响应哈希和规范化行哈希应同时保存。
- 不得把腾讯行情观察、公告事实、经典 baseline 或模拟结果写成真实 LLM 生成或真实回测结果。
