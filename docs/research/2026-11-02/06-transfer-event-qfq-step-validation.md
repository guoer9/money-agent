## 价格边界核算

公告转增比例为每 10 股转增 4 股，即股份变动比例 `0.4`。在不考虑现金红利和配股的情况下：

```text
理论参考价 = 2026-06-09 bfq 收盘 / (1 + 0.4)
           = 102.500 / 1.4
           = 73.2142857143
```

腾讯 qfq 在 2026-06-09 的收盘为 `73.214`，按三位小数四舍五入与理论参考价一致。

边界观察：

| 指标 | 数值 |
| --- | ---: |
| 2026-06-09 qfq/bfq 比值 | 0.714282926829268 |
| 2026-06-10 qfq/bfq 比值 | 1.000000000000000 |
| 比值乘法台阶 | `+40.000546343595%` |
| 2026-06-09 → 06-10 qfq 收益 | `-1.248395115688%` |
| 2026-06-09 → 06-10 bfq 收益 | `-29.463414634146%` |

可写结论：

- qfq/bfq 比值台阶精确出现在公告指定的除权日边界。
- `+40.000546%` 的台阶与“每 10 股转增 4 股”在样本中一致；前一日 bfq 收盘除以 `1.4` 后与 qfq 前收一致，说明该样本的 qfq 历史价格被缩放到了除权后的尺度。
- 这支持把“日期对齐 + 比值台阶 + 规则公式核对”作为股份事件的数据质量检查，而不是只检查现金分红。

不可写结论：

- 不能据此宣布腾讯复权公式已经验证；腾讯没有公开算法，且四舍五入、基准日、复权链和其他事件会改变具体实现。
- 不能把 qfq/bfq 的绝对比值当成复权因子；`06-09` 的绝对比值本来就不是 1。
- 不能把 qfq 收益当作可交易收益；缺少持有、税费、到账和执行模型。
- 不能证明历史 qfq 永不回写；本样本只证明某次下载中的边界行为。
- 不能把“10转4股”与 `fh_sh=""` 解释为“现金比例 0 且字段完整”；更准确的项目侧表述是：股份事件可能不适用现金字段，接口未提供可用于现金账本的数值。

- 交易所规则文本规定除权除息时点和参考价公式；S4 是托管副本，正式归档层级受限。
- 腾讯响应中的 `FHcontent` 和 `fh_sh` 是供应方返回值；本轮没有腾讯公开字段说明，因此“空字符串对股份事件表示不适用”只是项目侧归一化假设。

### 本项目推断（尚未代码验证）

1. 事件账本至少应分开保存：公告 ID、公告日期、股东大会日期、股权登记日、除权日、方案基数、实施基数、现金分红、送股、转增、配股、股份变动比例、事件类型、原文 URL 和原始文件哈希。
2. 对股份事件不能沿用 `fh_sh = 每股现金比例 × 10`；应先判断事件类型，再把现金分量和股份分量分别映射。`fh_sh=""` 应保留为“字段不适用或缺失”，不能静默转成 0。
3. 事件质量检查应至少包含两层：
   - 字段层：公告日期/比例 ↔ 供应方附属字段；
   - 价格层：公告边界 ↔ qfq/bfq 比值台阶 ↔ 规则公式的理论参考价。
4. 事件账本应保存“方案披露基数”和“实施基数”以及实际转增股数，避免把披露后总股本变化误判为方案不一致。
5. 当前只能把腾讯 qfq 用作研究型复权快照；不能把它写成 PIT 数据源，也不能用本样本反推完整复权因子。

## 可复用结论

- 混合现金和股份事件的审计不能只存一个“分红比例”；至少要有现金、送股、转增、配股等分量及各自是否适用。
- `djr/cqr` 可与公告登记日/除权日对齐；`FHcontent` 可作为事件线索，但不是公开字段规范。
- 股份数量变化事件的 qfq/bfq 台阶可以落在公告除权日，且本样本台阶与 `1/(1+0.4)` 的尺度变化一致。
- 规则公式核对必须按事件发生时点选规则；2026-07-06 生效的规则不能用于 2026-06-10 的事件。
- 供应商价格与交易所规则公式一致，只说明样本层面可解释；不等于供应商算法认证、PIT 认证或真实回测。
- 审计应同时保存公告 PDF 哈希、查询记录哈希、qfq/bfq/hfq 原始响应哈希、规范化价格行哈希和事件字段换算规则。
