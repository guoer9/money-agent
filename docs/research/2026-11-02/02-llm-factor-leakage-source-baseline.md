## 来源与原文依据

### S1. Alpha-GPT（LLM 因子挖掘，一手论文）

- 标题：Alpha-GPT: Human-AI Interactive Alpha Mining for Quantitative Investment
- URL：https://arxiv.org/abs/2308.00016v2
- 作者：Saizhuo Wang, Hang Yuan, Leon Zhou, Lionel M. Ni, Heung-Yeung Shum, Jian Guo
- 首次提交：2023-07-31；本版本更新：2025-09-20；访问：2026-11-02
- 类型：arXiv 论文原文；EMNLP 2025 System Demonstration Track
- 原文依据：
  - 论文提出以 LLM 作为人机交互中介的 alpha mining 范式，并用 Alpha-GPT 系统实现。
  - 实验使用中国和美国股票的盘中量价数据、OHLCV、VWAP、行业数据，以及时序、截面、分组和逐元素算子。
  - 论文报告 WorldQuant IQC 2024 的评价在官方比赛期间实时进行，并明确区分 in-sample 与 out-of-sample score。
  - 论文报告搜索增强过程中同时观察 in-sample 与 out-of-sample IC，并讨论样本外 IC 在初升后趋稳及约第 15 次迭代附近收敛。
- 对本项目的适用性：
  - 支持把 LLM 生成因子表达为受控算子组合，而不是自由执行代码。
  - 支持在实验记录中分别保存生成来源、开发/验证指标和样本外指标。
  - 支持以“迭代收益是否继续泛化”而不是只看训练 IC 决定是否继续搜索。
- 限制：
  - 这是论文作者的系统与比赛结果，不是本项目实验结果。
  - 论文未提供可复现的本项目数据、代码或 LLM 调用记录；不能据此声称本项目已有真实 LLM 能力。
  - 比赛实时评价降低未来信息泄漏风险，但不等于证明其全部研究流程不存在选择偏差。

### S2. scikit-learn 官方文档：数据泄漏

- 标题：Common pitfalls and recommended practices — Data leakage
- URL：https://scikit-learn.org/stable/common_pitfalls.html
- 发布方：scikit-learn developers；文档未给出单一论文发布日期，按访问日期记录
- 类型：官方技术文档
- 原文依据：
  - 数据泄漏是“在构建模型时使用了预测时不可获得的信息”，会产生过度乐观的性能估计。
  - 文档建议先划分训练与测试集，再执行预处理；测试集不得参与 `fit`/`fit_transform`，训练得到的变换再用于测试集。
  - 文档把特征选择、标准化、插补和 PCA 等都列为可能泄漏的变换。
- 对本项目的适用性：
  - 因子计算、缺失处理、缩尾、标准化、分位切分和模型拟合都必须明确“只在哪个时间段拟合”。
  - 不能因为最终只报告 validation 指标，就忽略预处理是否使用了 validation 或 test 的分布信息。
- 限制：
  - 通用机器学习文档，不覆盖金融标签重叠、公司行动和交易执行等特殊问题。
  - 本项目是否逐项满足，需要在代码和数据层面另行验证。

### S3. scikit-learn 官方文档：TimeSeriesSplit

- 标题：sklearn.model_selection.TimeSeriesSplit
- URL：https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html
- 发布方：scikit-learn developers；访问：2026-11-02
- 类型：官方 API 文档
- 原文依据：
  - 该类按时间顺序生成训练/测试索引，适用于常规交叉验证会导致“用未来数据训练、在过去数据上评价”的场景。
  - 每折测试集覆盖相同时间跨度，训练集从过去数据累积。
  - `gap` 参数表示在每折测试集之前从训练集末尾排除的样本数，可用于显式隔离相邻窗口。
- 对本项目的适用性：
  - 本项目已有按退出日期 purge 的声明；时间序列切分还必须同时考虑因子回看窗口和标签持有期，否则仅 purge 标签仍可能泄漏。
  - `gap` 可作为设计参照，但本项目当前协议并非直接调用该 API；不能据此声称已实现 `gap`。
- 限制：
  - 官方文档要求样本等间距；金融交易日、停牌和不同股票覆盖需要额外处理。
  - `TimeSeriesSplit` 本身不处理横截面相关性、标签重叠或交易成本。

## 交叉结论（来源事实 + 本项目推断分开）

### 来源支持的事实

1. LLM 可以生成结构化 alpha 表达式，但必须与确定性评价和真实反馈相连；生成器本身不等于有效因子。
2. 时间顺序切分、purge/gap、点时数据和冻结 OOS 是不同层次的防护，不能互相替代。
3. 迭代搜索会放大选择偏差；尝试次数和反馈历史必须进入审计记录。
4. 预处理和因子变换只能在训练/开发段拟合；测试段不得参与任何选择。
5. 可审计系统应保存数据、协议、候选、调用和冻结产物的版本/哈希。

### 对本项目的设计推断（尚未实现验证）

1. 每份 LLM 因子记录至少包含 `prompt_sha256`、`model`、`temperature`/随机参数（若适用）、`candidate_sha256`、`data_sha256`、`protocol_version`、`trial_index`、`feedback_segment`、`frozen_at`。
2. 最终测试访问应由独立入口控制：开发 worker 无权读取测试标签；冻结候选必须先写入不可变清单，再由独立评价步骤读取测试集。
3. 因子 AST 解释器除了拒绝未来窗口函数，还应检查算子回看窗口与标签持有期的边界，并记录每次运行的完整日历和 purge 区间。
4. 对同一候选不应使用验证集反复调参后再把最终验证结果当作独立证据；需要区分“候选发现反馈”和“候选确认结果”。
5. 归档应保留总试验数、被淘汰候选与淘汰原因，不能只展示最终入选因子。
