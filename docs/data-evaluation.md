# 行情、因子与评价协议

## 数据来源和口径

行情由 `thesis.acquisition` 从腾讯 `fqkline` HTTP 接口下载。每只股票在同一次请求中使用相同的起止日期、640 条上限和 `qfq` 参数，解析 `qfqday` 的 `date/open/close/high/low/volume` 字段；成交量沿用接口手数单位。前复权收盘同时作为 `adj_close` 标签价格。代码拒绝悄悄回退至未复权 `day` 股票数据。下载原文、请求 URL、UTC 时间、HTTP 状态、字节数与 SHA-256 均写入 `runtime/data/raw/` 和清单；Parquet 面板也按实际字节计算 SHA-256。上证指数的原始 `day` 记录仅用于统一交易日历，不进入股票面板。

当前固定股票池是 `sh600000, sh600009, sh600016, sh600028, sh600030, sh600036, sh600048, sh600050, sh600104, sh600111, sh600276, sh600309, sh600519, sh600585, sh600690, sh600887, sh601088, sh601166, sh601318, sh601398, sh601668, sh601857, sz000001, sz000002, sz000063, sz000333, sz000651, sz000858, sz002415, sz300750`。它便于复算和展示，不是历史时点成分股，带有明确幸存者偏差，不能代表当时可投资全市场。腾讯返回下载时点的前复权快照，不提供历史时点公司行动因子；结果可能因后续公司行动而改变。单个代码一次只请求同一 640 根区间，不通过移动起点或拼接多次请求扩展历史。成交量没有换算，停牌、零量、非正价格、非有限值、OHLC 次序错误以及重复键均不进行填补；重复键上的所有行都排除。清洗报告记录排除计数。

腾讯接口对每个代码最多返回 640 根，超过可用范围时返回窗口内的最近记录。清单记录实际起止日、股票逐只行数、日历覆盖、是否截断和固定股票池说明。即使部分代码请求失败，只要不足 10000 条有效记录、共同日历不完整或指数日历请求失败，获取过程也会落盘错误与原响应，然后失败退出，不生成占位面板。

## 交易时点和标签

因子在日期 `t` 收盘后计算。`h=1` 的统计持有期收益为：

```text
adj_close[t+2] / adj_close[t+1] - 1
```

因此以 `t+1` 收盘价作为入场价，以 `t+2` 收盘价作为退出价。滞后、滚动窗口、截面排序与标签都按显式共享交易日历对齐；缺少某股票的某日价格时，后续相应窗口和标签保持缺失，不以前值或后值补齐。表达式由有限 AST 解释器计算，只接受白名单字段、算术和有限的时间序列/逐日截面算子，不调用 `eval`、`exec`，也不接受属性、索引、导入或未来窗口。

每个分段只收录信号日期落在该段内且退出日期不晚于该段结束日的行。分段边缘的未完成标签因此被 purge，训练与验证不会共享退出日。基线程序在读取 Parquet 时还将读取上限限制在验证段结束日；测试段不进入因子计算、收益标签、评价或基线选择。v1.2 归档所有预先定义的经典因子，仅报告验证期结果，并把最终测试标为 `reserved_not_run`。

## 指标含义

- 每个交易日独立计算横截面 Pearson IC 和 Spearman Rank IC（平均秩处理并列值）；少于 5 个有效股票、因子为常数或标签为常数的当天结果是 `null`。
- ICIR / Rank ICIR 是有效日 IC 均值除以日 IC 样本标准差（`ddof=1`），不年化。只有一个有效日或标准差为零时返回 `null`。
- 覆盖率 = 分段 purge 后同时有有限因子值和有限标签的行数 / 有限标签行数；没有可评价标签时返回 `null`。
- `quantiles` 是前端直接使用的跨日聚合数组 `[{group, mean_return}]`。每个交易日先按因子值切成最多五个等量组；相同因子值不拆开。每组先算当日个股等权平均，再对有效日平均，避免股票多的日期获得额外权重。某日无法形成五个真实分组时，不产生伪造组值。
- `daily_quantiles` 额外保留逐日组收益与样本数，供审计使用；它与聚合数组由同一批真实逐日结果计算。

分层收益是统计性持有期收益，未计入费用、滑点、涨跌停、停牌执行限制或成交可达性，不应解释为回测净值或可交易组合业绩。

## 归档 schema

`runtime/artifacts/baselines.json` 是普通 JSON，使用严格有限数值序列化。前端核心契约如下：

```json
{
  "dataset": {
    "id": "...", "source": "...", "start": "YYYY-MM-DD", "end": "YYYY-MM-DD",
    "rows": 0, "instruments": 0, "sha256": "...", "adjustment": "...",
    "quality": {}, "splits": {"train": ["...", "..."], "validation": ["...", "..."], "test": ["...", "..."]}
  },
  "protocol": {"id": "...", "label": "...", "entry": "...", "exit": "...", "ic": "..."},
  "factors": [{
    "id": "...", "name": "...", "expression": "...", "description": "...",
    "segment": "validation", "origin": "baseline",
    "metrics": {"ic_mean": null, "rank_ic_mean": null, "ic_ir": null, "rank_ic_ir": null, "coverage": null, "valid_ic_days": 0},
    "daily": [{"date": "...", "ic": null, "rank_ic": null}],
    "quantiles": [{"group": 1, "mean_return": null}]
  }],
  "generated_at": "..."
}
```

允许额外审计字段：协议细节、有效/配对/已 purge 行数、逐日分层、分布、来源固定股票池、质量限制、测试集状态和未解决局限。每项因子注明 `origin: baseline`，不会包装成 LLM 生成、反馈改进或最终测试结果。

## 复算

在仓库根目录使用项目虚拟环境运行：

```sh
.venv/bin/python -m thesis.acquisition --output runtime/data --start 2024-01-01 --end 2026-10-30
.venv/bin/python -m thesis.baselines --root .
.venv/bin/python -m pytest tests/test_research.py tests/test_acquisition.py -q
```

每次重新下载会生成新的原始响应批次并替换当前面板、日历和清单。运行归档前会校验面板 SHA-256 和分段顺序；归档文件采用临时文件加原子替换。
