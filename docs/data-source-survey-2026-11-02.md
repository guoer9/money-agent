# A 股研究数据源调研：零预算、自建采集与 AKShare

调研日期：2026-11-02。范围：当前系统、供应方官方文档、社区源码、BaoStock 登录诊断及 AKShare 实测。用户最新明确 **零预算、允许 AKShare、参考 AKQuant、取数希望一分钟内且稳定性优先**。没有更换生产数据源，没有购买权限；已完成一次独立的 A 股当前证券全市场原始日线采集验证，但没有把它发布为产品研究快照。

最新选型为 **AKShare 与必要的最小站点适配器 + 自建调度/缓存/质量层 + 本地真实数据快照**，复用 Qlib 格式并参考 AKQuant 的文件化数据处理。BaoStock 由目标主源降为备选参考，不再以其登录成功阻塞主线。Tushare、RQData 等只作背景比较，不作为项目的付费前置条件。

当前生产数据仍是腾讯归档。后续独立验证已取得当前 A 股 5,576 只证券的新浪原始日线，共 11,393,279 条窗口记录；东财日线分层样本 60/60 成功，新浪复权因子试点 30/30 成功。全市场原始日线仍未通过复权、公司行为、交易状态和历史退市覆盖验收，因此没有发布为研究集。最新架构、性能目标及真实边界见 `docs/superpowers/specs/2026-11-02-stable-data-ingestion-design.md`，取代前序以 BaoStock 为主源的建议。BaoStock 失败证据保留，不继续反复探测。

全市场终态和质量边界见 `docs/a-share-full-market-test-2026-11-02.md` 及 `docs/evidence/2026-11-02/a-share-full-market-test.json`。本次采集期间用户主动开关 VPN；DNS 从 `198.18.*` 合成地址恢复到公网地址、路由从 `utun6` 变为 `en0` 后，东财同参数请求恢复 HTTP 200。该证据支持把 VPN 状态作为网络上下文记录，但没有隔离出具体规则，不能将东财此前失败写成接口永久不可用或付费限制。

## 1. 当前数据究竟来自哪里

已核对 `thesis/acquisition.py` 和 `runtime/data/manifest.json`：

| 项目 | 当前实际情况 |
| --- | --- |
| 来源 | 腾讯财经 `fqkline` HTTP 接口；不是交易所直连数据，也不是 RD-Agent 自带数据库 |

| 已有证据 | 原始 HTTP 响应、下载清单、文件/价格指纹、交易日历及质量记录 |
| 尚缺内容 | 全历史证券主表、历史股票池、独立复权/公司行为、财务、完整交易状态、涨跌停价、行业历史版本等 |

640 是当前接入方式的请求条数和观察到的截断范围，不据此断言腾讯所有产品或接口都只有这些历史数据。腾讯当前适配器没有可用于本项目的稳定服务、历史修订或再分发授权证明；公开 HTTP 可访问不能代替这些证明。

当前规模可以验证系统流程，不足以支持全市场泛化或跨长时期的实证结论。这是针对本课题实验目标的判断，不是说增加行数本身能改善因子表现。

### 前序 BaoStock 官网核验，保留作背景

已读取用户提供的 `https://www.baostock.com/mainContent?file=home.md`。该站为动态页面，本机通过页面公开脚本实际使用的只读文档接口取得正文，没有登录或绕过访问限制。官网正文及“每日更新”文档的抓取摘要与指纹见 `docs/evidence/2026-11-02/baostock-official-home.json`，原始正文保留在独立验证目录。见 S19–S21。

- 首页明确将基础平台描述为免费、无需注册。2026-09-21 的 0.9.4 更新增加可选 API Key/VIP 节点支持；本机已安装该版本，这不足以解释为匿名服务需要付费。
- 2026-07-10 的 0.9.3 增加 `query_daily_history_k_AStock`、`query_daily_history_k_ETF` 与 `query_daily_adjust_factor`。日频方案可据此分为“初次按证券补历史”和“后续按交易日期增量”；每日接口文档示例使用普通 `bs.login()`，但实际权限、历史跨度、分页和返回完整性尚未实测。不能把一个查询调用等同于一个网络请求或保证只需两次请求更新全市场。
- BaoStock 官网公布日线 17:30、复权因子 18:00 完成入库，分钟线为 20:00；其它财务报告为次日 01:30。前序方案建议从 18:15 开始检查 BaoStock 日线与因子，验收通过才发布。这是该供应方的文档时点和历史建议，不作为当前 AKShare 各底层来源的统一更新时间；新来源分别验证数据水位。
- 官网另列 ETF、指数、部分季度财务与业绩报告等覆盖；这些是可逐步验收的扩展方向，不要求额外采购，也不能把“部分财务”写成完整财务数据库。首页部分时间范围表述不完全一致，逐接口实测优先于笼统覆盖承诺。

### 付费路线仅作背景

官方现行个人权限表列出：120 积分档为免费不复权日线；2000 积分档为 200 元/年；5000 积分档为 500 元/年。各接口仍有自己的门槛和限额，分钟、实时、新闻、公告等另有独立权限。积分是访问门槛，不是每次调用扣减的余额。见 S01、S16。

这些差异说明低价档并非完整研究数据包。本项目不以购买这些权限来解决当前问题，优先验收免费来源的实际能力。价格为调研日官网个人报价，不代表账户已取得权限。

### 财务数据最关键的区别

Tushare 利润表文档列有 `ann_date`、`f_ann_date` 和 `end_date`，分别涉及公告/实际公告日期和报告期，不能只按报告期把数据回填到历史交易日。见 S07。

RQData 的 `get_pit_financials_ex` 明确提供 `date`、`statements`、`info_date` 等参数/字段；默认查询日期是最新日期。即使用了带 PIT 名称的接口，也必须显式指定研究时点，并核验各次披露和修订记录。见 S13。

对本系统，建议保存报告期、公告可得时间、修订标识、采集时间和来源。只有日期、没有发布时间时，制定保守的下一交易日可用规则并披露。供应商提供复权因子或公告日期，都不能单独证明整个数据集满足严格历史时点可得性。

以下为本项目建议，不是供应商已交付的清单。

| 优先级 | 数据资产 | 最小内容 | 主要作用 |
| --- | --- | --- | --- |
| P0 | 长历史不复权日线 | OHLC、昨收、成交股数、成交金额、交易日、证券代码 | 扩大横截面和时间跨度，保留交易价格口径 |
| P0 | 复权与公司行为 | 因子、除权除息生效日、分红/送转/配股记录、版本与来源 | 构造可解释的研究价格并排查异常跳变 |
| P0 | 证券与日历主表 | 交易所、板块、上市退市日、交易日历；保留已退市证券 | 建立历史可投资集合与可追溯排除规则 |
| P0 | 交易状态 | 停复牌、ST/风险警示、涨跌停价、上市初期等状态 | 为后续可交易性评价提供依据 |
| P1 | 历史成分与行业 | 成分变更、生效区间、权重、行业分类版本与有效期 | 指数池实验、行业/规模分组和稳健性分析 |
| P1 | 每日估值与股本 | 市值、流通股本、换手率、估值口径与单位 | 构造规模/流动性控制与更丰富的因子 |
| P1 | 财务与披露 | 三大报表、指标、实际公告时间、原始/修订版本 | 基本面因子及与量价因子的对照 |
| P2 | 分钟、新闻、研报、宏观 | 事件时间、采集时间、更新频率、权限范围 | 在日频主实验稳定后扩展具体研究问题 |

建议以 2015-01-01 至最近已确认完整交易日为首版扩容目标。先验收少量股票与短窗口，再做历史成分池和市场分层样本，最后考虑全 A 股离线研究。北交所、不同板块和退市历史分别统计覆盖，不用“今日股票名单”回填全部年份。数据规模按实际有效观测计数，不按当前证券数量乘历史交易日制造完整性数字。此为目标范围，不是已经下载的数据覆盖。

BaoStock 的独立复权因子不能替代逐类分红、送转、配股事件明细；其日线交易状态也不等于已提供完整的逐日涨跌停价、板块规则与交易限制。P0 清单中未取得的数据必须保持缺失标记，相关回测结论限制在实际可验证的范围内。

扩容时另建数据集版本，保留现有基线结果和已披露的切分。当前已预留最终测试为 2026-04-22 至 2026-10-30；本轮不修改、不执行该区间。新增早期历史不应把已查看过的验证数据重新称为独立最终测试；如后续确需调整，先重订实验协议并披露已有研究暴露。

## 4. 数据层与前端应怎样承接

建议维持现有原始响应和指纹机制，逐步扩展为“供应方适配器 → 原始层 → 统一标准层 → 带历史可得时间的研究快照 → 因子评价 → 展示 API”。原始层保留来源身份；统一层将成交量规范为股、金额规范为元，并记录转换规则。交易用不复权价与研究用复权价分别保存。

不能将停牌期间的供应商占位 K 线当作真实可成交记录。BaoStock 文档明确描述其停牌日可能为平价、零成交量记录；应保留原始状态，并在研究和可交易性视图中明确处理，而不是把所有零成交量行简单视为下载失败。见 S08。

前端优先展示与研究结果直接相关的真实数据资产：

1. 数据源、频率、使用范围说明、最后成功更新时间和当前数据集版本；日线与复权因子分开显示水位，尚未齐备时显示“快照待发布”。
2. 股票数、历史覆盖、上市/退市/板块覆盖、字段可用性矩阵。
3. 采集任务进度、失败重试、断点恢复和清洗前后数量。
4. 缺失/停牌/异常价格的区分，以及跨源抽样差异。
5. 因子、实验归档与输入数据集的关联，研究快照和行情更新状态分别标明。

这些资产可支撑数据大屏的密度和交互，不要求先引入实时或 tick 数据。页面可以采用盘后日频快照，但必须标明时间和频率，不把刷新页面描述为实时行情到达。

AlphaAgent 的 `alphaagent/data/market_fetch.py` 也可参考联网获取与离线 panel 构建分离，固定提交为 `b42cb397025510da44355db9dcf278304321f589`。它使用 Tushare 的实现不是当前主源；`fundamental_fetch.py` 对同一报告期只保留最新公告行，也不能直接作为保存全部历史修订的 PIT 数据仓库。该本地快照的授权正文仍需另核实，本轮不复制其代码。

源码是实现参考，不能替代数据授权、字段契约或供应方现行规则。研究文档中的后续任务描述也没有被作为执行指令运行。

## 6. 接入验收与风险边界

### 本机 BaoStock 实测

环境为产品 `.venv`、Python 3.10.18、BaoStock 0.9.4。只使用匿名公开端点、串行连接，没有 API Key、并发请求或批量采集。

- 第一次调用停在 `bs.login()` 内超过 5 分钟；8 秒 socket 默认超时未终止该等待。核对进程后发送 SIGINT，已退出；证券、日线、因子、日历查询均未开始。
- 第二次为单次诊断，父进程设置 20 秒硬超时；仅在子进程内观察 socket 并遇 EOF 立即停止，不修改安装包。实测 TCP 到 `public-api.baostock.com:10030` 成功，发送 57 字节后首次接收返回 0 字节，登录未成功。
- 诊断将 EOF 转为异常后，SDK 返回 `10002007`（网络接收错误）。原 SDK 的 `send_msg` 循环没有空字节退出分支，这能解释第一次等待未因 socket 超时结束；本次证据不能确定连接被关闭的上游原因，也不能据此断言账号收费、被封禁或数据服务不可用。
- 当前取得行情样本 **0 行**。证据：`docs/evidence/2026-11-02/baostock-probe.json`。不将 TCP 建连成功或 Python 正常退出视为数据接入验收通过。

### 扩容验收

建议先用覆盖沪深不同板块、上市/退市、停牌/ST、现金分红/送转/配股等情形的小型固定样本验收，再扩大下载。验收包含唯一键、日历覆盖、原始单位、复权事件、历史成员、公告可得时间、重复请求与增量重放；价格差异保留原因，不强行抹平。

| 风险 | 本项目的控制重点 |
| --- | --- |
| 已隔离：BaoStock 登录失败 | 不再阻塞主线；保留证据，避免无限重试。当前真实数据集继续保留腾讯来源标识 |
| 较低：本地真实快照与盘后展示 | 来源明确、缓存可读、原子发布；新鲜数据更新成功率单独统计 |
| 中等：多源核对与历史池 | 复权算法、证券映射、月度快照生效时间、退市覆盖及异常隔离 |
| 较高：严格 PIT 财务和公司行为 | 修订版本、公告时间、供应方回写、事件类别和历史可得性证据 |
| 额外成本：分钟/实时与外部分发 | 独立权限、带宽/存储、使用和展示授权；不作为当前日频论文的前置条件 |

### AKShare 与 AKQuant 的新增核验

隔离环境实际安装 AKShare 1.18.88，产品 `.venv` 未变。新浪日历返回 8,797 个日期；原始 K 线单证券样本可离线解码。随后完成当前 A 股 5,576 只证券的原始日线采集：2015-01-01 至 2026-10-30 窗口有 11,393,279 行，所有目标证券成功取得非空窗口数据，文件哈希无失败，首轮批次耗时 2,894.643 秒。该结果证明当前网络条件下原始日线批量链路可完成，但不等于复权研究集、历史全市场或一分钟全量补库已经完成。

东财分层试验覆盖沪主板、科创板、深主板、创业板和北交所各 6 只，2025 年第一季度原始与前复权请求 60/60 成功、耗时 29.845 秒；新浪复权因子独立试点 30/30 成功、共 228 条因子记录。此前东财/因子超时保留为历史现场，不能覆盖；本轮恢复与用户手动切换 VPN 同期发生，具体网络规则仍未隔离。全市场原始日线中 36 只证券有价格质量异常，上市后交易日缺口需结合停牌/交易状态继续解释，因此当前 `research_ready=false`。证据见 `docs/a-share-full-market-test-2026-11-02.md`、`docs/evidence/2026-11-02/a-share-full-market-test.json` 和隔离运行目录。

AKQuant 官方数据指南的 A 股示例直接调用 AKShare，并支持本地文件与 DataFeed；本轮只阅读文档，没有安装或测试引擎。教材中的网络失败后随机行情兜底不进入本系统。文档指纹见 `docs/evidence/2026-11-02/akquant-docs.json`。

现有 19,190 行 Parquet 的五次本地全表读取，首次约 0.218 秒，后续约 0.002 秒。该结果仅支持本地快照读路径的可行性，不等于 API、前端、扩容或一分钟取数已达标。批量稳定性、停牌/退市覆盖、复权一致性和学校授权范围仍未验收。BaoStock 登录问题已从主线隔离，AKShare 与必要的最小适配器按底层来源逐项验收；当前生产归档仍为腾讯数据。

## 7. 后续接入顺序与展示验收

这是后续工程拆分。本轮已完成独立全市场原始日线采集验证，但没有执行产品数据层发布或全市场下载替换：

1. **建立独立稳定层**：新增采集任务库与 worker，复用现有幂等和事件机制；设置供应方预算、子进程硬截止、有限重试和熔断。保留研究 worker 的单任务锁，不再反复探测 BaoStock 登录。
2. **拆分最小日频适配器**：参考固定版本 AKShare 源码，先离线重放已取得的新浪原文；基础日线、复权、股本、日历、新闻分别采集。上游失败保留原文与错误，零量、空值、停牌占位和请求失败分别记录；同一供应方的库调用和自建 HTTP 适配共享并发预算。
3. **不可变快照与研究质量门槛**：先用训练期短窗口核验唯一键、单位、复权事件、证券日期范围及 Qlib 读回。快照存到新目录，原子发布引用；未满足复权等实验依赖时不标记研究就绪，不覆盖现有腾讯归档或实验身份。
4. **前端数据总控优先接入**：沿用 Vue 3 工作台，展示数据截至日与采集时间、来源健康、覆盖热力图、字段矩阵、任务时间线和溯源抽屉。页面 GET 只读本地；手动更新返回任务 ID。旧真实快照可用与最近更新失败同时展示，无合格缓存时显示空状态。
5. **30 只池的一分钟验收**：在已有历史缓存下验证一次日常增量，分别报告批次耗时、新鲜更新成功率与完整性；60 秒截止后延后未完成项，旧缓存可读不算更新成功。积累至少 20 个真实更新观测后再报告 P95；首次历史补库单独计时。本轮全市场首轮补库约 48 分 15 秒，不能承诺全市场多年历史一分钟完成。
6. **扩池与补充资产**：试点通过后评估 300 只和从 2015 年起的历史扩容，保留历史成员与退市覆盖缺口。再验证新闻、季度财务和 AKQuant 策略级回测适配；RD-Agent 保持研究主体，严格 PIT、完整新闻历史和实时行情不作为首版前置条件。

完整任务、接口契约、测试与风险分区见 `docs/superpowers/plans/2026-11-02-stable-data-ingestion.md` 和对应设计。本轮已形成全市场采集验证证据，但产品 worker、快照发布、前端数据总控和一分钟增量指标仍待实施验收。
